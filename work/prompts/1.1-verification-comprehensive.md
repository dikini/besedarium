#### Duality Verification (Task 1.1.4)

- **Basic duality**: Test fundamental Send/Recv, Choice/Offer duality
- **Complex duality**: Test parallel, recursive construct duality
- **IO consistency**: Verify duality respects IO capabilities
- **Metadata consistency**: Test that duality preserves metadata properly

```rust
#[cfg(test)]

    use super::*;
    
    #[test]
    fn test_send_recv_duality() {
        type SendProto = TChanSend<
            CommMetadata<DefaultChan, TextLabel>,
            Server, Client, String, InputAction, TChanEnd
        >;
        type RecvProto = TChanRecv<
            CommMetadata<DefaultChan, TextLabel>,
            Client, Server, String, OutputAction, TChanEnd
        >;
        
        // Test compile-time duality checking
        fn assert_dual<P1, P2>() where P1: IsDual<P2, Output = TTrue> {}
        assert_dual::<SendProto, RecvProto>();
    }
    
    #[test]
    fn test_choice_offer_duality() {
        type ChoiceProto = TChanChoice<
            CommMetadata<DefaultChan, BinaryLabel>,
            Server,
            (TChanEnd, TChanEnd),
            OutputAction
        >;
        type OfferProto = TChanOffer<
            CommMetadata<DefaultChan, BinaryLabel>,
            Server,
            (TChanEnd, TChanEnd),
            InputAction
        >;
        
        assert_dual::<ChoiceProto, OfferProto>();
```

## Common Issues and Solutions

### Compilation Issues

- **Trait bound errors**: Check that all required bounds are specified
- **Type inference failures**: Add explicit type annotations where needed
- **Recursive type issues**: Ensure proper base cases for recursive constructs

### Duality Issues  

- **False positives**: Check metadata and IO consistency requirements
- **False negatives**: Verify all duality rules are correctly implemented
- **Performance**: Ensure duality checking doesn't cause excessive compilation times

### Projection Issues

- **Incorrect endpoint types**: Verify role analysis logic
- **Missing projections**: Ensure all protocol constructs have projection implementations
- **Validation failures**: Check that validation logic correctly identifies errors

## Success Criteria

The verification is successful when:

1. All components compile without errors or warnings
2. All verification tests pass
3. Complex realistic protocols can be defined and verified
4. Performance is acceptable for practical use
5. Error messages are clear and actionable
6. Integration with existing codebase is smooth
