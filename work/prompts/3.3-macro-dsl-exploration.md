# Task 3.3: Macro-Based DSL Exploration for Protocol Definition

## Objective

Explore and develop a macro-based Domain Specific Language (DSL) to simplify protocol definition for users of the Besedarium session type library. This exploration focuses on derive and attribute macros first, before considering more complex procedural macros.

## Background

The current Besedarium library provides a comprehensive type-level approach to session types with explicit protocol construction using types like `TChanSend`, `TChanRecv`, `TChanChoice`, etc. While powerful and type-safe, the current API can be verbose for complex protocols.

Key insights from documentation analysis:
- Extensive procedural macro patterns documented in `docs/runtime-implementation-patterns.md`
- Existing basic macro infrastructure in `src/macros.rs`
- Strong foundation for dual protocol generation research
- Need for improved developer ergonomics without sacrificing type safety

## Requirements

### 1. Derive Macros for Common Patterns

Implement derive macros that automatically generate common protocol boilerplate:

- `#[derive(Role)]` - Automatically implement `Role` trait for user types
- `#[derive(Message)]` - Implement `Message` trait with serialization support
- `#[derive(Protocol)]` - Generate protocol infrastructure for user-defined protocols
- `#[derive(Dual)]` - Automatically generate dual protocols

### 2. Attribute Macros for Protocol Enhancement

Create attribute macros for declarative protocol specification:

- `#[protocol]` - Enhanced protocol definition syntax
- `#[role(Name)]` - Role specification with metadata
- `#[endpoint]` - Endpoint behavior specification
- `#[session_type(Type)]` - Session type annotations

### 3. Declarative Macros for Common Operations

Expand existing declarative macro infrastructure:

- `protocol!{}` - Natural syntax for protocol definition
- `session!{}` - Session setup and management
- `roles!{}` - Multi-role definition
- `messages!{}` - Batch message type definition

### 4. Foundation for Procedural DSL

Establish patterns for future procedural macro development:

- Parsing protocol specification syntax
- Code generation patterns
- Integration with existing type system
- Error reporting and diagnostics

## Detailed Design Musings

### Core `#[protocol]` Macro Vision

Based on research into existing patterns and documentation, the `#[protocol]` macro should provide a natural, arrow-based syntax for protocol specification:

```rust
#[protocol(
    io = "sync",
    metadata = "standard",
    buffer_size = 1024,
    timeout_ms = 5000
)]
protocol ChatProtocol {
    roles: Client, Server;
    
    Client -> Server: Login(username: String);
    Server -> Client: LoginResponse(success: bool);
    
    if success {
        loop {
            Client -> Server: Message(content: String) | Logout;
            match {
                Message(content) => Server -> Client: Ack,
                Logout => end
            }
        }
    } else {
        end
    }
}
```

### Property Specification Architecture

The macro should support multi-level property specification:

1. **Protocol-level properties**: IO type, metadata handling, default timeouts
2. **Role-level properties**: Specific capabilities, resource limits
3. **Message-level properties**: Serialization hints, validation rules

```rust
#[protocol(io = "async", metadata = "custom")]
protocol FileTransfer {
    roles: 
        Client(buffer_size = 2048, max_connections = 1),
        Server(buffer_size = 8192, max_connections = 100);
    
    Client -> Server: FileRequest(path: String) @timeout(30s);
    Server -> Client: FileResponse { 
        Found(metadata: FileMetadata) @chunked(size = 1024),
        NotFound
    };
}
```

### Integration with Existing Type System

The macro must generate code that integrates seamlessly with existing traits:

- `SupportsActionIO` for IO capability specification
- `CommMetadata` for metadata handling
- `Role`, `Protocol`, `Message` traits
- Dual protocol generation via `IsDual` trait

### Code Generation Strategy

#### 1. Message Type Generation

Convert protocol messages into proper Rust types:

```rust
// From: Client -> Server: Login(username: String);
// Generate:
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Login {
    pub username: String,
}

impl Message for Login {
    type Metadata = StandardMetadata;
    // ... implementation
}
```

#### 2. Protocol Type Construction

Generate session type structures using existing primitives:

```rust
// From protocol specification
// Generate:
type ClientProtocol = TChanSend<Login, TChanRecv<LoginResponse, ...>>;
type ServerProtocol = TChanRecv<Login, TChanSend<LoginResponse, ...>>;
```

#### 3. Role Projection Generation

Automatically generate role projections using established patterns:

```rust
impl Protocol for ChatProtocol {
    type Client = ClientProtocol;
    type Server = ServerProtocol;
}

impl Role for Client {
    type Protocol = ClientProtocol;
    // ... implementation
}
```

### Property Handling Design

#### IO Capability Specification

```rust
#[protocol(io = "sync")]  // SupportsActionIO<SyncIO>

```

### Parsing Infrastructure

#### Attribute Parsing

```rust
struct ProtocolAttributes {
    io_type: IoType,
    metadata_type: MetadataType,
    buffer_size: Option<usize>,
    timeout_ms: Option<u64>,
    // ... other properties

```

#### Protocol Grammar

```rust
// Simplified grammar for protocol specification
Protocol := "protocol" Ident "{" RoleDecl MessageFlow* "}"
RoleDecl := "roles:" RoleList ";"
MessageFlow := Role "->" Role ":" Message ("@" Properties)? ";"
Message := Ident "(" FieldList ")" | Choice
Choice := "{" (Ident "(" FieldList ")")+ "}"
```
