# Task 1.1.4: Duality Checking Implementation

## Objective

Implement the `IsDual` predicate/trait for verifying duality between protocol specifications, considering `CommMetadata`, message types, and `IO` consistency. This trait provides compile-time verification that two protocol types are duals of each other, which is essential for ensuring safe multiparty communication.

## Context and Requirements

### Duality Definition

From `docs/duality.md`, duality follows these rules:

| Construct                | Dual() Definition                                |
|-------------------------|--------------------------------------------------|
| Init                    | Init                                             |
| End                     | End                                              |
| Offer {l_i: P_i}        | Choice {l_i: Dual(P_i)}                          |
| Choice {l_i: P_i}       | Offer {l_i: Dual(P_i)}                           |
| Send<M, Msg, P>         | Receive<M, Msg, Dual(P)>                         |
| Receive<M, Msg, P>      | Send<M, Msg, Dual(P)>                            |
| Par(P, Q)               | Par(Dual(P), Dual(Q))                            |
| Seq(P, Q)               | Seq(Dual(P), Dual(Q))                            |
| Rec X. P                | Rec X. Dual(P)                                   |
| Continue X              | Continue X                                       |

### Key Invariants

1. **Involution**: `Dual(Dual(P)) == P` for all protocols `P`
2. **Metadata Consistency**: Dual actions must have matching `CommMetadata` 
3. **Message Type Consistency**: Dual actions must exchange the same message types
4. **IO Capability Compatibility**: Dual endpoints must have compatible `IO` capabilities

use std::marker::PhantomData;

/// Type-level trait for checking duality between two protocol types
///
/// Returns TTrue if P and Q are duals of each other, TFalse otherwise
pub trait IsDual<P, Q> {
    type Output: Bool;
}

/// Helper type alias for cleaner usage
pub type IsDualOutput<P, Q> = <() as IsDual<P, Q>>::Output;

/// Marker trait for types that can participate in duality checking
pub trait DualityCheck: Send + Sync + 'static {}

// Implement for all protocol types
impl<T: GlobalProtocol> DualityCheck for T {}
impl<T: LocalProtocol> DualityCheck for T {}

## Debugging Guide

### Common Issues

1. **Infinite type recursion**:
   - Issue: Recursive protocols cause infinite trait resolution
   - Solution: Use termination conditions and proper trait bounds

2. **Metadata mismatch errors**:
   - Issue: `CommMetadata` doesn't match between dual types
   - Solution: Ensure same channel and label types in dual constructs

3. **IO capability conflicts**:
   - Issue: `SupportsActionIO` bounds not satisfied
   - Solution: Verify IO types implement required action capabilities

4. **Role ordering confusion**:
   - Issue: Send/Recv roles swapped incorrectly
   - Solution: Remember duality swaps sender/receiver: `Send<A,B>` dual to `Recv<B,A>`

### Debugging Steps

1. **Check trait bounds**: Ensure all required trait bounds are specified
2. **Verify metadata consistency**: Check that `CommMetadata` types match exactly
3. **Test simple cases first**: Start with basic Send/Recv duality before complex cases
4. **Use type aliases**: Simplify complex types with aliases for easier debugging
5. **Check recursion termination**: Ensure recursive protocols have proper base cases

### Error Messages

Expected error patterns:

- `IsDual<P, Q>` trait not implemented → Types are not dual
- `EqualsTrue` not satisfied → Duality check returned False
- `SupportsActionIO<AIO>` not satisfied → IO capability mismatch
- `CommMetadata<C, L>` bounds not met → Channel/label type mismatch
