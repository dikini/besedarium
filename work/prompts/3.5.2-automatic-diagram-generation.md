# Task 3.5.2: Automatic Diagram Generation from Protocol Definitions

## Phase 2 Specification: Derive Macro-Based Protocol Visualization

### 1. Overview

Building on Phase 1's foundation (manual Mermaid diagram embedding), Phase 2 implements automatic diagram generation directly from protocol type definitions. This creates a seamless workflow where developers define protocols and get documentation diagrams "for free."

**Key Innovation**: Leverage the existing derive macro infrastructure to generate Mermaid sequence diagrams automatically from protocol structure analysis.

### 2. Phase 2 Objectives

- **Automatic Generation**: Generate Mermaid diagrams from protocol definitions without manual intervention
- **Type-Level Analysis**: Extract protocol flow information from Rust type system using derive macros
- **Documentation Integration**: Seamlessly embed generated diagrams in doc comments
- **API Compatibility**: Work with existing protocol examples and maintain current API patterns

### 3. Current State Analysis

**Foundation Available**:
- ✅ `simple-mermaid` integration for diagram embedding
- ✅ Working protocol examples with verified API compatibility (`examples/verify_protocol_examples.rs`)
- ✅ Existing derive macro infrastructure (`besedarium-derive` crate)
- ✅ Understanding of protocol structure from type system

**Protocol Structure Mapping Available**:
- `TChanSend<From, To, _, _, Msg, Next, _>` → `From->>To: Msg`
- `TChanRecv<To, From, _, _, Msg, Next, _>` → `From->>To: Msg`
- `TChanChoice<Role, _, _, Branch1, Branch2, _>` → `alt` blocks
- `TChanEnd<_, _, _>` → End of sequence

### 6. Technical Considerations

#### 6.1 Rust Stable Constraints

- **No specialization**: Use marker type dispatch for different protocol types
- **No reflection**: Rely on derive macro code generation for introspection
- **Type-level programming**: Work within stable trait system limitations

#### 6.2 Protocol Structure Analysis

**Key Challenge**: Extract meaningful sequence from nested type aliases.

**Solution Pattern**:
```rust
// From this type structure:
type CustomerSendsOrder = TChanSend<Customer, Agency, _, _, Order, CustomerReceivesQuote, _>;
type CustomerReceivesQuote = TChanRecv<Customer, Agency, _, _, Quote, CustomerMakesChoice, _>;

// Generate this sequence:
// Customer->>Agency: Order
// Agency->>Customer: Quote
// alt Accept
//   Customer->>Agency: Accept
// else Reject
//   Customer->>Agency: Reject
// end
```

#### 6.3 Error Handling and Validation

- Validate protocol structure consistency during introspection
- Provide clear error messages for unsupported protocol patterns
- Handle recursive protocols (like retry patterns) appropriately
