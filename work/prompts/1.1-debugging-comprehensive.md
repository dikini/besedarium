# Task 1.1 Debugging and Troubleshooting Prompt

## Overview

This prompt provides comprehensive debugging strategies for troubleshooting issues during implementation of Task 1.1 subtasks (foundation types, global protocols, local endpoints, duality checking, and projection).

## Common Issues and Debugging Strategies

### 1. Foundation Types Issues (Task 1.1.1)

#### Issue: Trait Bound Errors in CommMetadata

**Symptoms:**

```
error[E0277]: the trait bound `MyChannel: ChanId` is not satisfied
```

**Debugging Steps:**

1. Verify trait implementations:

```rust
// Check that your channel type implements ChanId
impl ChanId for MyChannel {
    // Implementation required
}
```

2. Check trait bounds in CommMetadata:

```rust
// Ensure proper bounds
pub struct CommMetadata<C: ChanId, L: MsgLbl> {
    _phantom: PhantomData<(C, L)>,
}
```

3. Debug with explicit type annotations:

```rust
// Make types explicit to identify the issue
let metadata: CommMetadata<DefaultChan, TextLabel> = CommMetadata::new();
```

#### Issue: ActionIOTMarker Compilation Failures

**Symptoms:**

```
error[E0277]: the trait bound `MyAction: ActionIOTMarker` is not satisfied
```

**Debugging Steps:**

1. Verify ActionIOTMarker implementations:

```rust
// Check implementations for standard actions
impl ActionIOTMarker for InputAction {}
impl ActionIOTMarker for OutputAction {}
impl ActionIOTMarker for BiDirectionalAction {}
```

2. Check SupportsActionIO constraints:

```rust
// Debug with explicit bounds
fn test_supports_action_io<T>() 
where 
    T: SupportsActionIO<InputAction> + SupportsActionIO<OutputAction>
{
    // Test implementation
}
```

3. Use type assertions for debugging:

```rust
// Compile-time assertion to check trait implementation
const _: fn() = || {
    fn assert_action_io<T: ActionIOTMarker>() {}
    assert_action_io::<MyAction>();
};
```

### 2. Global Protocol Types Issues (Task 1.1.2)

**Symptoms:**


**Debugging Steps:**

1. Check GlobalProtocol implementation:

```rust
impl<M, S, R, T, IO, P> GlobalProtocol for TChanSend<M, S, R, T, IO, P>
where
    M: CommMetadata,
    S: Role,
    R: Role,
    IO: ActionIOTMarker,
    P: GlobalProtocol,
{
    // Implementation
}
```

2. Debug with minimal examples:

```rust
// Start with simplest case
type MinimalSend = TChanSend<
    CommMetadata<DefaultChan, TextLabel>,
    Server,
    Client,
    String,
    InputAction,
    TChanEnd
>;

// Test GlobalProtocol implementation
fn test_global_protocol<T: GlobalProtocol>() {}
test_global_protocol::<MinimalSend>();
```

3. Check recursive constraints:

```rust
// Ensure continuation protocols implement GlobalProtocol
impl GlobalProtocol for TChanEnd {}
// Check that P: GlobalProtocol in all recursive cases
```

#### Issue: Complex Protocol Construction Failures

**Symptoms:**

```

```

**Debugging Steps:**

1. Break down complex types:

```rust
// Break into components
```

2. Use type aliases for debugging:


### 4. Duality Checking Issues (Task 1.1.4)

#### Issue: IsDual Trait Implementation Errors

**Symptoms:**

```
error[E0277]: the trait bound `TChanSend<...>: IsDual<TChanRecv<...>>` is not satisfied
```

**Debugging Steps:**

1. Check basic IsDual implementations:

```rust
// Debug with explicit type parameters
impl<M, S, R, T, IO1, IO2, P1, P2> IsDual<TChanRecv<M, R, S, T, IO2, P2>> 
for TChanSend<M, S, R, T, IO1, P1>
where
    M: CommMetadata,
    S: Role,
    R: Role,
    IO1: ActionIOTMarker,
    IO2: ActionIOTMarker,
    // Check IO consistency constraint
    (IO1, IO2): IODualityConsistent,
    P1: IsDual<P2>,
{
    type Output = <P1 as IsDual<P2>>::Output;
}
```

2. Debug metadata consistency:

```rust
// Check that metadata types match exactly
type Proto1 = TChanSend<CommMetadata<DefaultChan, TextLabel>, /* ... */>;
type Proto2 = TChanRecv<CommMetadata<DefaultChan, TextLabel>, /* ... */>;  // Same metadata
```

3. Debug IO consistency requirements:

```rust
// Test IO duality rules
fn test_io_duality() {
    // Input/Output should be dual
    assert_io_dual::<InputAction, OutputAction>();
    // BiDirectional should be self-dual
    assert_io_dual::<BiDirectionalAction, BiDirectionalAction>();
}
```

4. Use debugging macros:

```rust
macro_rules! debug_duality {
    ($p1:ty, $p2:ty) => {
        const _: fn() = || {
            fn assert_dual<T1, T2>() where T1: IsDual<T2, Output = TTrue> {}
            assert_dual::<$p1, $p2>();
        };
    };
}

debug_duality!(MySendProto, MyRecvProto);
```

#### Issue: Complex Duality Checking Failures

**Symptoms:**

```
error: implementation of `IsDual` is not general enough
```

**Debugging Steps:**

1. Check recursive duality constraints:

```rust
// Ensure proper recursive bounds
impl<M, R, Choices1, Choices2, IO1, IO2> IsDual<TChanOffer<M, R, Choices2, IO2>>
for TChanChoice<M, R, Choices1, IO1>
where
    M: CommMetadata,
    R: Role,
    Choices1: IsDual<Choices2>,  // Check choices duality
    (IO1, IO2): IODualityConsistent,
{
    type Output = <Choices1 as IsDual<Choices2>>::Output;
}
```

2. Debug with helper traits:

```rust
// Use helper traits for complex conditions
trait ChoicesDual<Other> {
    type Output: TypeBool;
}

// Implement for specific choice patterns
impl ChoicesDual<(T2, T4)> for (T1, T3)
where
    T1: IsDual<T2>,
    T3: IsDual<T4>,
{
    type Output = TypeAnd<
        <T1 as IsDual<T2>>::Output,
        <T3 as IsDual<T4>>::Output
    >;
}
```

### 5. Projection Issues (Task 1.1.5)

#### Issue: Project Trait Implementation Errors

**Symptoms:**

```
error[E0277]: the trait bound `TChanSend<...>: Project<Server>` is not satisfied
```

**Debugging Steps:**

1. Check basic Project implementations:

```rust
// Debug with explicit role analysis
impl<M, S, R, T, IO, P> Project<S> for TChanSend<M, S, R, T, IO, P>
where
    M: CommMetadata,
    S: Role,
    R: Role,
    P: Project<S>,
{
    type Output = EpSend<M, T, IO, <P as Project<S>>::Output>;
}

impl<M, S, R, T, IO, P> Project<R> for TChanSend<M, S, R, T, IO, P>
where
    M: CommMetadata,
    S: Role,
    R: Role,
    P: Project<R>,
{
    type Output = EpRecv<M, T, /* dual IO */, <P as Project<R>>::Output>;
}
```

2. Debug role involvement:

```rust
// Test projection for different roles
type GlobalSend = TChanSend</* Server -> Client */>;

// Test sender projection
type SenderProj = <GlobalSend as Project<Server>>::Output;  // Should be EpSend
// Test receiver projection  
type ReceiverProj = <GlobalSend as Project<Client>>::Output; // Should be EpRecv
// Test third party projection
type ThirdPartyProj = <GlobalSend as Project<Monitor>>::Output; // Should be EpSkip
```

3. Use helper traits for debugging:

```rust
// Debug with role containment checking
trait ProjectDebug<P, R> {
    type RoleInvolved: TypeBool;
    type ProjectionOutput: LocalProtocol;
}

impl<P, R> ProjectDebug<P, R> for ()
where
    P: Project<R>,
    P: ContainsRole<R>,
{
    type RoleInvolved = <P as ContainsRole<R>>::Output;
    type ProjectionOutput = <P as Project<R>>::Output;
}
```

## Debugging Tools and Macros

### Type Debugging Macros

```rust
// Macro to print type information at compile time
macro_rules! debug_type {
    ($t:ty) => {
        const _: fn() = || {
            fn type_name_of<T>(_: &T) -> &'static str {
                std::any::type_name::<T>()
            }
            // This will show in error messages
            let _: $t = unreachable!();
        };
    };
}

// Macro to assert trait implementations
macro_rules! assert_trait_impl {
    ($t:ty: $trait:path) => {
        const _: fn() = || {
            fn assert_impl<T: $trait>() {}
            assert_impl::<$t>();
        };
    };
}
```

### Duality Debugging Macros

```rust
macro_rules! debug_duality {
    ($p1:ty, $p2:ty) => {
        const _: fn() = || {
            fn assert_dual<T1, T2>() where T1: IsDual<T2> {
                // This will reveal the Output type in error messages
                let _: <T1 as IsDual<T2>>::Output = unreachable!();
            }
            assert_dual::<$p1, $p2>();
        };
    };
}
```

### Projection Debugging Macros

```rust
macro_rules! debug_projection {
    ($proto:ty, $role:ty) => {
        const _: fn() = || {
            fn assert_project<P, R>() where P: Project<R> {
                // This will show the projection result type
                let _: <P as Project<R>>::Output = unreachable!();
            }
            assert_project::<$proto, $role>();
        };
    };
}
```

## Systematic Debugging Approach

### 1. Isolate the Issue

- Start with the minimal failing case
- Remove complexity until the issue is isolated
- Add complexity back incrementally

### 2. Check Trait Bounds

- Verify all required trait implementations exist
- Check that trait bounds are properly specified
- Use explicit type annotations to clarify requirements

### 3. Verify Type Consistency

- Check that types match exactly where required
- Verify metadata consistency across protocol types
- Ensure IO parameter consistency

### 4. Test Edge Cases

- Test with empty protocols
- Test with single-element choices
- Test with roles not involved in communications

### 5. Use Compilation Tools

```bash
# Get detailed error information
cargo check --verbose

# Check with different optimization levels
cargo check --release

# Use expanded macros for debugging
cargo expand --test test_name
```

## Success Indicators

You've successfully debugged when:

1. All compilation errors are resolved
2. All tests pass
3. Complex protocols compile without errors
4. Error messages are clear and actionable
5. Performance is acceptable for realistic use cases

## When to Seek Help

Consider asking for help when:

1. Errors persist after systematic debugging
2. Performance is unacceptably slow
3. Type system limitations are encountered
4. Integration with existing code is problematic

Remember: Type-level programming in Rust can be complex. Systematic debugging and incremental development are key to success.
