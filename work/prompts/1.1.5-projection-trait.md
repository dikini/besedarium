# Task 1.1.5: Project<P, Role> Trait Implementation

## Objective

Implement the `Project<P, Role>` trait for projecting Global Protocols to Local Endpoint Types, ensuring `SupportsActionIO` checks. This covers Tasks 1.1.5a through 1.1.5f:

- **1.1.5a**: Core `Project<P, R>` trait with `Output: LocalProtocol` associated type
- **1.1.5b**: Projection for `TChanSend` to `EpSend`/`EpRecv` based on role involvement
- **1.1.5c**: Projection for `TChanChoice` to `EpChoice`/`EpOffer` constructs
- **1.1.5d**: Projection for `TChanPar`, `TChanRec`, `TChanEnd` constructs
- **1.1.5e**: Helper traits (`ProjectChoices`, `Not<Role>`, `ValidProjection`) for complex projections
- **1.1.5f**: `ProjectionError` type and validation mechanisms

## Prerequisites

- **Task 1.1.1 must be completed**: Foundation types must be implemented
- **Task 1.1.2 must be completed**: Global Protocol Types must be implemented  
- **Task 1.1.3 must be completed**: Local Endpoint Types must be implemented
- **Task 1.1.4 should be completed**: Duality checking provides validation
- **Reference documentation**: Study the projection definitions in `docs/duality.md`
- **Existing projection system**: Understand current `ProjectRole` trait in `src/protocol/transforms/projection.rs`

## Context and Requirements

### Current State Analysis

The existing codebase has a `ProjectRole` trait but it uses older protocol types. We need to:

1. **Extend or replace**: Create new projection for channel-aware types
2. **Maintain compatibility**: Ensure existing projections continue to work
3. **Add validation**: Include `SupportsActionIO` checks during projection
4. **Error handling**: Provide clear error types for invalid projections

### Implementation Strategy

We'll create a new projection system specifically for the enhanced channel-aware types while maintaining backward compatibility with the existing system.

### Task 1.1.5a: Core Project<P, R> Trait

**Location**: Create `src/projection.rs` or extend `src/protocol/transforms/projection.rs`

#### Base Project Trait

```rust
use crate::foundation::{GlobalProtocol, LocalProtocol, Role, SupportsActionIO, ActionIOTMarker};
use crate::types::{Bool, TTrue, TFalse};

/// Core projection trait for channel-aware protocols
///
/// Projects a Global Protocol `P` to a Local Endpoint Type for role `R`
pub trait Project<P, R> 
where
    P: GlobalProtocol,
    R: Role,
{
    /// The resulting local protocol for role R
    type Output: LocalProtocol;
    
    /// Validate that the projection is well-formed
    type IsValid: Bool;
    
    /// Error type if projection fails
    type Error: ProjectionError;
}

/// Type alias for cleaner projection usage
pub type ProjectOutput<P, R> = <() as Project<P, R>>::Output;

/// Type alias for projection validation
pub type ProjectIsValid<P, R> = <() as Project<P, R>>::IsValid;

/// Trait for types that can be projected
pub trait Projectable: GlobalProtocol + Send + Sync + 'static {}

// Implement for all global protocol types
impl<T: GlobalProtocol> Projectable for T {}
```

/// Enhanced projection trait that includes IO capability validation
pub trait ProjectWithIO<P, R, IO>

    R: Role,

## Debugging Guide

### Common Issues

1. **Type parameter explosion**:
   - Issue: Too many generic parameters in projection traits
   - Solution: Use type aliases and helper traits to manage complexity

2. **Infinite recursion in projections**:
   - Issue: Recursive protocols cause infinite trait resolution
   - Solution: Add proper termination conditions and bounds checking

3. **Role equality checking failures**:
   - Issue: `RoleEq` trait bounds not satisfied
   - Solution: Ensure all role types implement proper equality checks

4. **IO capability validation failures**:
   - Issue: `SupportsActionIO` bounds not met
   - Solution: Verify IO types support required action capabilities

5. **Case analysis complexity**:
   - Issue: Too many projection cases to handle
   - Solution: Use helper traits for case-specific logic

### Debugging Steps

1. **Start simple**: Test basic Send/Recv projections before complex constructs
2. **Check trait bounds**: Ensure all required bounds are specified correctly
3. **Use type aliases**: Simplify complex types for easier debugging
4. **Test incrementally**: Add one projection case at a time
5. **Verify role relationships**: Check that role equality works correctly

### Error Message Patterns

Common error patterns to watch for:
- `Project<P, R>` trait not implemented → Missing projection implementation
- `ProjectIsValid<P, R>: EqualsTrue` not satisfied → Projection validation failed
- `SupportsActionIO<AIO>` not satisfied → IO capability mismatch
- `RoleEq<R>` bounds not met → Role equality checking failed
